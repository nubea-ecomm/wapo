02 / WhatsApp

Let your customer connect WhatsApp

The instance administrator first configures the Meta application in Console → Configuration → WhatsApp. Check onboarding_ready on GET /v1/me before creating a setup link.

Create a setup link 
curl -X POST "$WAPO_URL/v1/customers/CUSTOMER_ID/setup_links" \
  -H "X-API-Key: $WAPO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "allowed_connection_types": ["coexistence", "dedicated"],
    "language": "es"
  }'

Share data.url with the customer. Links expire after 30 days by default and can be revoked. Authorized list and get requests can retrieve the URL; its token is encrypted at rest.

Connection type Customer experience
coexistence Continue using WhatsApp Business App alongside the API, subject to Meta eligibility.
dedicated Connect a number dedicated to the WhatsApp Cloud API.

Offering both types lets the customer choose on the hosted page. Send just one type to restrict the link. After authorization, listen for whatsapp.phone_number.created or list GET /v1/connections.

Already have a configured Cloud API number?

Use POST /v1/connections with channel: "whatsapp", its Meta phone number ID, WABA ID and access token. Wapo verifies number ownership before storing the credentials.

Send a WhatsApp message

Choose a connected number from GET /v1/connections. Use its Wapo id, not its Meta phone number ID, as connection_id.

Send text 
curl -X POST "$WAPO_URL/v1/messages" \
  -H "X-API-Key: $WAPO_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: order-123-confirmation" \
  -d '{
    "connection_id": "con_example",
    "payload": {
      "to": "5491112345678",
      "type": "text",
      "text": { "body": "Your order is ready." }
    }
  }'

Free-form text requires an open WhatsApp customer service window. Outside that window, use an approved template in the message payload. Meta policies and message pricing still apply.

Follow the conversation

List GET /v1/conversations, load GET /v1/conversations/{id}/messages, then reply with POST /v1/conversations/{id}/messages. Patch a conversation to assign it or change its status to open or closed.

A successful send means Meta accepted the request. Delivery and read status arrive later through events; do not treat an accepted response as delivery confirmation.

Project branding

A project is the tenant isolation boundary. Set its name, logo, accent color and hosted-link theme in Console → Configuration → Project, or use PATCH /v1/project.

Existing setup links use the latest saved identity. Logos accept PNG or JPEG data URLs up to 5 MiB decoded. Send an empty logo_data_url to remove a logo. Omitted fields stay unchanged.

Update branding 
curl -X PATCH "$WAPO_URL/v1/project" \
  -H "X-API-Key: $WAPO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name":"Example store","branding":{"accent_color":"#2563eb","theme":"light"}}'
