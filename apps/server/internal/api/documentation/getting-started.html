01 / Get started

Your first request

Sign in to the console, select a tenant and open API keys. Create a key and save it when it is shown: the full secret is returned only once.

Terminal 
export WAPO_URL="http://localhost:8080"
export WAPO_API_KEY="<your-tenant-api-key>"

curl "$WAPO_URL/v1/me" \
  -H "X-API-Key: $WAPO_API_KEY"

A successful response identifies the tenant and whether hosted WhatsApp onboarding is configured.

200 / application/json 
{
  "data": {
    "project_id": "tenant_example",
    "compatibility_mode": false,
    "onboarding_ready": true
  }
}
Choose the right credential.

A tenant key is for your server-side integration. Console passwords and administrator sessions are for managing the platform.

Authentication

Send your tenant key in the X-API-Key header. Authorization: Bearer <key> is also accepted. Tenant keys have full access to their own tenant; they cannot switch to another tenant with a header.

Credential Scope Where to use it
Tenant API key One tenant /v1/*
Console session Global administrator /admin/v1/*
Operator API key Global administrator Server-side platform administration

Administrators calling tenant endpoints must select an active tenant with X-Tenant-ID. Use tenant keys in customer integrations. Keep keys and Meta access tokens on your server.

Customers and connections

A tenant is an isolated workspace. A customer represents a business inside that workspace. A connection is an authorized WhatsApp number owned by the tenant or associated with a customer.

Tenant→Customer→WhatsApp connection

Create a customer using an external ID from your own system. That ID must be unique within the tenant.

Create a customer 
curl -X POST "$WAPO_URL/v1/customers" \
  -H "X-API-Key: $WAPO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Example store",
    "external_customer_id": "store_123",
    "email": "owner@example.com",
    "metadata": { "plan": "standard" }
  }'

Use the returned data.id as CUSTOMER_ID in the next step.
