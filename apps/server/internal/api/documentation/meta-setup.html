Configure your Meta application

Configure the instance once. Customers then authorize their own numbers through setup links.

Choose the installation model

Wapo is open source. A business running its own installation supplies its own Meta app and account credentials. An operator connecting other businesses through a hosted installation completes the provider enrollment and review required for that app. Each self-hosted operator repeats the applicable setup. Open-source licensing does not grant Meta permissions or determine who controls an installation's data.

1. Create an app and copy its credentials

Open Meta for Developers. Create an app with the WhatsApp use case and associate your business portfolio. In App settings → Basic, copy App ID and reveal App Secret.

Variable Where to get it
META_APP_ID App settings → Basic → App ID.
META_APP_SECRET App settings → Basic → App Secret → Show.
META_EMBEDDED_SIGNUP_CONFIG_ID Facebook Login for Business → Configurations. Create a WhatsApp Embedded Signup configuration and copy its Configuration ID. The Embedded Signup Builder may expose this configuration for your app.
META_VERIFY_TOKEN You generate this value. It is not issued by Meta. Use the same value in the webhook configuration.
META_GRAPH_VERSION The Graph API version used by this deployment, currently configured as v24.0. Check compatibility before changing it.
PUBLIC_URL Your API's public HTTPS address. Meta must reach it. Local development needs an HTTPS tunnel to port 8080.
WEB_ORIGIN The console origin, including scheme and port. This controls Wapo CORS; it does not configure Meta domains.

The configuration ID belongs to the login configuration. It is different from App ID, business portfolio ID, WABA ID and Phone Number ID.

Enroll as a provider for customer onboarding

Open Use cases → WhatsApp → Customize → Quickstart, then Become a Tech Provider → Continue onboarding. Select the independent Tech Provider route if you operate independently, or the Solution Partner route matching your actual arrangement. The owner reviews the terms. Continue to Onboarding and complete the associated business verification. Provider enrollment, business verification, App Review and publication are separate.

If Onboarding is blank, return to Quickstart and check enrollment. In an observed setup, the onboarding pagelet redirected to Quickstart and failed with error 1007; completing enrollment restored the page. This does not explain every error 1007. After enrollment, check WhatsApp → Embedded Signup Builder and Facebook Login for Business → Configurations for the WhatsApp variation. A general Facebook login configuration alone is insufficient.

Dashboard URL recipes (replace APP_ID and BUSINESS_ID):

https://developers.facebook.com/apps/APP_ID/use_cases/customize/wa-dev-quickstart/?product_route=whatsapp-business&business_id=BUSINESS_ID&use_case_enum=WHATSAPP_BUSINESS_MESSAGING&selected_tab=wa-dev-quickstart
https://developers.facebook.com/apps/APP_ID/use_cases/customize/onboard/?product_route=whatsapp-business&business_id=BUSINESS_ID&use_case_enum=WHATSAPP_BUSINESS_MESSAGING&selected_tab=onboard
https://developers.facebook.com/apps/APP_ID/app-review/submissions/?business_id=BUSINESS_ID

2. Save the server environment

.env 
META_APP_ID=<app-id>
META_APP_SECRET=<app-secret>
META_EMBEDDED_SIGNUP_CONFIG_ID=<configuration-id>
META_VERIFY_TOKEN=<your-random-token>
META_GRAPH_VERSION=v24.0
PUBLIC_URL=https://api.example.com
WEB_ORIGIN=https://console.example.com

Keep secrets in the server environment. Do not prefix them with VITE_. Leave the existing database, encryption and administrator settings in place.

Generate a verification token 
openssl rand -hex 32

Copy the generated value into META_VERIFY_TOKEN, then recreate the services from the repository root:

Apply configuration 
docker compose up -d --build migrate api worker

3. Configure domains and the webhook

Add the public API hostname to App Domains. Allow its HTTPS setup-page origin in the JavaScript SDK settings of Facebook Login for Business. Review Valid OAuth Redirect URIs for your login configuration. A webhook callback is a separate endpoint.

In the WhatsApp webhook configuration, use the selected project's callback shown in Console → Configuration → WhatsApp: 

https://api.example.com/hooks/meta/PROJECT_ID

Enter your META_VERIFY_TOKEN as the verification token and choose Verify and save. Subscribe to messages and account_update. For Coexistence, also enable smb_message_echoes, history and smb_app_state_sync where Meta makes them available. Wapo subscribes the authorized WABA with a project callback override during setup.

4. Verify the installation

Use “Verify configuration” in the console. This checks whether environment values are present; it does not validate App Review or account permissions.

To test the webhook handshake, export the same values in your shell and replace PROJECT_ID:

Webhook handshake 
curl -G "$PUBLIC_URL/hooks/meta/PROJECT_ID" \
  --data-urlencode 'hub.mode=subscribe' \
  --data-urlencode "hub.verify_token=$META_VERIFY_TOKEN" \
  --data-urlencode 'hub.challenge=wapo-check'

The response must be wapo-check. Then create a customer, generate a setup link, authorize a number and check its connection status. Coexistence requires an eligible WhatsApp Business App number and the corresponding signup configuration.

5. Connect external customers

Development mode is limited to app-role users. External businesses require the business verification, review and access requested by Meta. Check whatsapp_business_management, whatsapp_business_messaging and any additional permission required by your Embedded Signup configuration.

App Review checklist

Open Review → App Review or Edit App Review in Onboarding. Check the actual submission status: an onboarding card saying “In review” can still lead to a draft marked Not submitted (Sin enviar).

  1. Complete verification and Basic settings: icon, category, contact email, public privacy policy and data-deletion information for this installation.
  2. In Allowed usage, explain messaging and authorized account/template management. Review public_profile and any additional permission requested by your configuration. Describe implemented features and the actual operator of this open-source installation.
  3. Upload the recordings requested for each permission: send from Wapo and show receipt in WhatsApp for messaging; demonstrate template creation and management for management. Use real test workflows and hide credentials.
  4. Complete the required API calls and check the form's counters. The observed form required one call per WhatsApp permission and allowed up to 24 hours for recognition.
  5. In Data handling, identify actual hosting/service providers, the responsible person or entity and country. Answer government-request history and implemented policies truthfully. Open-source status does not replace these answers.
  6. Provide stable public reviewer access, dedicated test credentials and exact reproduction steps. An API tunnel does not expose a localhost console.
  7. Save and review the draft, submit when complete, monitor follow-up requests and complete Publish requirements before inviting external businesses.

A successful login code alone is not completed WhatsApp authorization: Wapo also needs the WhatsApp session event identifying the WABA. Verify sending, receiving, webhook delivery and template operations. Connection health may report payment or messaging restrictions even with a valid token. Local mocked tests do not establish production approval. Dashboard paths were observed on October 18, 2026 and can vary.

Manual connection credentials

For an existing Cloud API number, WhatsApp → API Setup shows its Phone Number ID and WABA ID. Use an authorized access token for that account in Connections → Connect WhatsApp → Use Meta credentials. The test token shown by Meta can expire. For a managed server integration, configure an authorized system user and account assets in your business settings.

These three values belong to a connection, not the global environment. Setup links obtain the customer's token through the server-side code exchange; the customer does not share your app secret.

Troubleshooting

Problem Check
Webhook verification fails Public HTTPS URL, correct project callback, matching verification token and restarted API.
Signup does not open App ID and Configuration ID from the same app, enabled JavaScript SDK login, allowed SDK domain and app-role access. For login without WhatsApp assets, check provider enrollment and the WhatsApp Builder configuration.
Missing permissions Account access, app review and advanced permissions in Meta.
Coexistence is missing Business App signup variation and number eligibility.
Variables remain missing Edit the server .env and recreate the API process. Reloading the console does not reload server variables.

Source: Meta's sample application and Meta's Embedded Signup collection. Dashboard labels can vary by app configuration.
