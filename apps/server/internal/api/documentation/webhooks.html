03 / Events

Receive signed webhooks

Register a public HTTPS endpoint and choose the events you need. The signing secret must contain at least 16 characters. Private and loopback destinations are blocked in a public deployment.

Subscribe to incoming messages 
curl -X POST "$WAPO_URL/v1/webhooks" \
  -H "X-API-Key: $WAPO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://your-app.example/webhooks/wapo",
    "secret_key": "<your-random-signing-secret>",
    "events": [
      "whatsapp.message.received",
      "whatsapp.message.delivered",
      "whatsapp.message.read"
    ]
  }'

Verify the request before parsing JSON

Compute HMAC-SHA256 over the exact raw request body using your signing secret. Compare its lowercase hexadecimal digest to X-Webhook-Signature using a constant-time comparison. The value has no sha256= prefix.

Node.js / signature verification 
import { createHmac, timingSafeEqual } from 'node:crypto'

export function verify(rawBody, signature, secret) {
  if (!/^[a-f0-9]{64}$/i.test(signature || '')) return false
  const expected = createHmac('sha256', secret).update(rawBody).digest()
  const received = Buffer.from(signature, 'hex')
  return received.length === expected.length &&
    timingSafeEqual(received, expected)
}
Header Purpose
X-Webhook-Event Event name, such as whatsapp.message.received.
X-Webhook-Signature HMAC-SHA256 of the raw payload.
X-Idempotency-Key Stable event ID. Deduplicate deliveries by this value.

Return a 2xx response promptly after accepting the event. Deliveries are at least once; retries and manual replay can produce duplicates. Failed deliveries retry up to eight total attempts with backoff. Inspect GET /v1/deliveries and retry failed items from the console or API.

Incoming events, status updates and Business App echoes are also recorded in GET /v1/events. Preserve your deduplication state when replaying events.
